# ComfyUI workflows

The app's two core flows as ComfyUI graphs, built from Comfy's partner nodes. Each comes in two formats:

| File | What it reproduces |
| --- | --- |
| `character-sheet.json`, `character-sheet.api.json` | Photos to a character: the 16:9 turnaround sheet from every photo, then the front, three-quarter, profile and full-body views from the photos plus that sheet |
| `still-first-video.json`, `still-first-video.api.json` | The Video studio's "Still first": a still with the character in it, then a clip animated from that frame. A second row does a shot without people as a cheap Seedance draft, then its 1080p final |

The `.json` files are the graph you open and edit. The `.api.json` files are the **Workflow (API)** format, for
sending to a ComfyUI server's `/prompt` route from a script.

## Open them

1. Use a current ComfyUI (desktop, portable or Comfy Cloud at [cloud.comfy.org](https://cloud.comfy.org)). Partner
   nodes need you signed in to a Comfy account with credits: they call the same providers the app does.
2. Drag the `.json` file onto the canvas, or use **Workflow → Open**.
3. Add the input images (below) to `ComfyUI/input/`, or pick them in each **Load Image** node.
4. Run.

### Inputs

- **character-sheet:** three photos of yourself named `my-photo-1.jpg`, `my-photo-2.jpg` and `my-photo-3.jpg`.
  Varied angles, good light, one face each. Add Load Image nodes for up to 10 and wire them into every Nano
  Banana node's next image slot.
- **still-first-video:** a character's sheet and front view, named `walt-sheet.jpg` and `walt-front.jpg`. The
  sample character's are in [`public/samples/`](../public/samples/). For your own character, unzip its `.portraius`
  file (it's a zip): use `sheet/turnaround.png` and `sheet/front.png`.

## Partner nodes used

| Node (as listed in ComfyUI) | Node ID | Model | Used in |
| --- | --- | --- | --- |
| Nano Banana 2.1 | `GeminiNanoBanana2V2` | Gemini Nano Banana 2.1, the app's image model | Both |
| MiniMax H3 First-Last-Frame to Video | `MinimaxHailuo03FirstLastFrameNode` | MiniMax H3 at 768P | Still first, with a character |
| ByteDance Seedance 2.5 First-Last-Frame to Video | `ByteDance2FirstLastFrameNode` | Seedance 2.5 Draft at 480p | Still first, without people |
| ByteDance Seedance 2.5 Draft to Final Video | `ByteDance2DraftToFinalVideoNode` | Seedance 2.5 at 1080p, from the draft's ID | Still first, without people |

Plus core nodes: Load Image, Save Image, Save Video, Preview as Text and a note.

## How they match the app

- **Same prompts.** The graphs are generated by [`src/lib/workflows/comfy.ts`](../src/lib/workflows/comfy.ts)
  from the app's own prompt code: the sheet template and view prompts in `lib/characters/sheet.ts`, and the prompt
  compiler in `lib/prompts/compile.ts` (reference legend, identity lock, scene, camera, realism). A test fails if
  the files here drift from the code; `npm run workflows` rebuilds them.
- **Same settings.** Nano Banana 2.1 at 2K with HIGH thinking (the app's "Best"), no system prompt, the sheet at
  16:9, views at 4:5 and 9:16, references in the order the prompt's legend names them.
- **People render on MiniMax H3.** The spec planned Seedance 2.5 for this flow, but Seedance refuses photoreal
  people as input images, so the app renders every clip with a person on H3 (decided October 19). The graph does
  the same. Seedance 2.5 keeps the shot without people, with the app's draft-then-final step: the final node starts
  bypassed. Paste the draft's `draft_task_id` from **Preview as Text**, turn the final and its Save Video back on,
  and run again. The draft node's seed is fixed, so it isn't drawn again.
- **What the graphs don't do.** No webcam consent check, identity score, automatic drift retry or realism pass:
  those live in the app. The `.portraius` node pack that would bring them into ComfyUI is P2 and isn't built.
- **Partner nodes go through Comfy's API proxy** rather than Comfy Router, so they bill to the signed-in account
  and serve the same models through ComfyUI's own integration.

## Checked against ComfyUI

`npm run workflows:check` (with `COMFY_API_KEY` in your shell) compares both `.api.json` files with the node
definitions ComfyUI publishes at Comfy Cloud's `/api/object_info`. It checks that every node exists, that every
input name is one the node takes (including the dotted names of dynamic inputs like `model.images.image_1`), and
that every choice is one of its options. It ran clean on October 20, 2026. Nothing executes, so it costs nothing.

The graphs haven't been run end to end yet: Comfy Cloud's API refuses keys from free-tier accounts, and there's no
local ComfyUI on the build machine. Opening a graph in Comfy Cloud and pressing Run is the quickest full check.
